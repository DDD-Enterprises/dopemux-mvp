## Findings (non-blocking)

- **F1 — LOW (pre-existing, not introduced):** `.claude/hooks/dcp_surface_guard.py::_repo_relative` (def ~lines 44–50) is purely lexical: `..` segments are never resolved, and an absolute path outside `project_root` is used verbatim after `ValueError`. A `file_path` like `<root>/x/../.github/workflows/ci-complete.yml` yields rel `x/../.github/workflows/ci-complete.yml`, which no `^`-anchored pattern matches — evading **every** `FORBIDDEN_PATHS` rule, not just workflows. *Impact:* the OS-resolved target is the real protected file, so this is a genuine pre-existing guard bypass. *Repair:* resolve with `Path(file_path).resolve().relative_to(project_root.resolve())` in a separate hardening change; out of scope here, not worsened by this PR.
- **F2 — LOW (pre-existing):** `red_lane_scanner.py` path-check loop applies `FORBIDDEN_PATHS` to raw `changed_files` strings with no normalization; `./`-prefixed, absolute, or doubled-separator forms evade path findings (fail-open for evasion; for the carved-out pair the doubled-separator form over-blocks, fail-safe). *Repair:* shared normalization helper; separate change.
- **F3 — INFORMATIONAL:** Python `$` matches before a trailing newline, so the literal string `.github/workflows/embedded-audit.yml\n` would evade the new regex. Such a string names a distinct file (newline in filename), never the real protected file — no realistic bypass; noted because the exempted string set is therefore technically not *exactly* two strings.
- **F4 — Test-coverage gap (minor):** no committed tests pin case-variant, traversal, separator, or whitespace edge inputs; behavior verified by reasoning only (all fail-safe).
