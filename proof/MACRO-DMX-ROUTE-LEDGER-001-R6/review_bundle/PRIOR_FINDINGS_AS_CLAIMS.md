- N1 | HIGH | Claim: the repaired code has not run in a real Claude Code session; all behaviour is covered by an offline mock-engine kit only. | Repair status claimed: not repaired in code; remains OPEN. The code before the repair was loaded live on 2026-10-30 (see limitation (i)); no live result for the frozen head is supplied (NOT_RUN).
- N2 | MEDIUM | Claim: `receiptDir` is not checked for symlinks (`$.fs.stat` is never called), an explicit absolute directory is allowed, and a trailing slash on the default value skips the state-directory check. | Repair status claimed: REPAIRED for symlinks and the trailing slash in 26414fef5 (D6: the receipt directory, or its nearest existing parent, is inspected with `$.fs.stat`; a symlink or a non-directory turns receipts off; a relative directory must resolve inside the project root; the default is compared without a trailing slash; a segment file that is a symlink turns receipts off before the first write). An absolute directory stays allowed by design (limitation (vii)). A later commit, 3d2af4b20, also turns receipts off when an existing receipt directory cannot be listed.
- N3 | MEDIUM | Claim: closed (rolled-over) segments stay in memory with all their receipts for the process lifetime, so memory grows linearly with receipts. | Repair status claimed: REPAIRED in 26414fef5 (D7: a closed segment is evicted after it has been written, except one that still holds an Agent request waiting for its spawn join; the counts and the last main-loop step do not depend on evicted receipts).
- N4 | MEDIUM | Claim: a failed write leaves the segment dirty and `session.end` schedules and awaits only one flush, so a failed final flush loses the dirty tail. | Repair status claimed: REPAIRED in 26414fef5 (D4: `flushAtEnd` makes one more awaited attempt if a segment is still unwritten; a second failure is counted in `receiptsFailed` and not retried). The same retry was later applied to `/clear` (61c371f28).
- N5 | MEDIUM | Claim: `session.end` with reason `clear` returns `next(e)` untouched, so after `/clear` receipts continue to the old session id's file. | Repair status claimed: CHANGED in 26414fef5 (D8) and again in 61c371f28: on `/clear` the mod flushes (one more try if the first write fails), keeps the status line, then resets its ledger so the next hook re-resolves the session id; if receipts are still unwritten the reset waits (`clearPending`) and nothing is dropped, and receipts recorded in between carry the old session id. Whether the host changes the session id on `/clear` is UNKNOWN (limitation (d) below); both outcomes are tested offline only.
- N6 | LOW | Claim: the unpinned-agent toast passed no `timeoutMs` and fell back to the host default, unlike the budget toasts which use 8000. | Repair status claimed: REPAIRED earlier, in 4fcdc9761, and present in the frozen head (the toast passes `TOAST_MS`).
