## Findings from the run (for the follow-up list)

1. **CI unit test fails on Linux**: `tests/unit/test_docs_no_envrc_recipe.py` parametrizes `.claude/CLAUDE.md`; the tracked file is `.claude/claude.md` (case-insensitive macOS hid it). Introduced in b2c6e3efa. Copilot flagged the same line.
2. **Build-only launch leaves an orphan runtime dir**: a first launch that exits with `LAUNCH_IMAGE_BUILDING` creates `<runtime>/dopemux-mvp-<hash>/` (build pid, build.log, compose.build.yml, mcp.env) without a registry entry or leases; `reap` joins on registry entries, so the dir is never reaped (`dopemux-mvp-2271` on this host). Low: no containers, no ports.
3. **Design §6 T7 names `hook_status.json`**; native hooks do not write it (Redis Streams activity events, kill-switched). Doc wording to fix.
4. **Unexplained 30 s stall** on the very first two launches (see T10). Not reproduced; worth a `DOPEMUX_LAUNCH_WAIT`-bounded retry on another host.
5. An untracked, git-ignored `.env` (1 KB) appeared in the acceptance worktree at the time of T7/T9; its content was not read (deny rule) and no M1 code path writes a repo-root `.env`; writer unknown.
6. Project-server approval: a never-set-up repo's first session shows "Pending approval" until the user approves the project's MCP servers once (Claude Code behaviour; init prints this step). Not a defect; worth a line in the how-to's "what you will see".
