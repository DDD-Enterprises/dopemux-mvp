## B1. codex F1 — a registry persistence failure still deletes the runtime dir and reports `reaped`

`src/dopemux/mcp/reap.py`: `_release_state` (line ~637) appends save errors to `report.errors` and returns normally; `_reap_one` (line ~671) catches only `LockBusy`, then `shutil.rmtree(cand.runtime_dir)` and `report.reaped.append(cand)`. Real persistence failures (corrupt-registry refusal, `OSError`) travel through that error-return channel (`locks.py` `save_state_locked` / `save_states_locked`), so a failed save loses the recovery artifacts (runtime dir) while leases stay active and the run says "reaped".

Required: make persistence success explicit. `_release_state` returns the list of error strings it recorded (keep appending them to `report.errors`). In `_reap_one`, after the full docker success path, if `_release_state` returned any error: keep the runtime dir, record a skip with a new reason `state_error` (containers are gone; registry/leases/dir stay for a later run, exactly like `registry_busy`), and do NOT append to `reaped`. In the partial-docker-failure branch the dir is already kept; make sure nothing there can append to `reaped` either. Add `state_error` wherever skip reasons are enumerated/typed/documented (search `registry_busy` in `src/`, `tests/` and `docs/02-how-to/mcp-setup-other-repos.md`; the how-to's reap section lists the skip reasons — add the new one with one line). Test: a `_release_state` whose save returns an error string (monkeypatch `save_states_locked`/`save_state_locked` to return `["boom"]`) → runtime dir still exists, `report.reaped == []`, one skip with reason `state_error`, the error text in `report.errors`; the state-only recovery on a later run still works (existing tests).

## B2. codex F2 — direct CLI `start`/`restart` are not serialized against the automatic reaper

`src/dopemux/mcp/lifecycle.py` `run_lifecycle` (line ~814): only the `stop` branch takes `instance_lock` (line ~1333). `restart` runs `_stop_services` then `_start_services` unlocked; `start` reaches `_start_services` unlocked. `reap._reap_one` assumes the instance lock excludes lifecycle mutations, so for an idle detached instance a reap can pass eligibility while a direct `dopemux mcp start/restart --repo X` proceeds, then stop/remove the instance and release its state mid-operation.

Ruled design (do not substitute a re-entrant lock; `instance_lock` stays a plain flock):
- Add keyword `hold_instance_lock: bool = True` to `run_lifecycle`. When `not dry_run` and `hold_instance_lock`, the `start` and `restart` branches run under ONE `instance_lock(runtime_dir)` acquisition (restart: both `_stop_services` and `_start_services` inside the same acquisition). The `stop` branch keeps its lock and also honours the flag. Dry runs never lock (as today).
- Compute `runtime_dir = runtime_dir_for_paths(project_root=..., worktree_hash=..., registry_path=reg_path)` once before the op branches and reuse it (the stop branch already computes it).
- Callers: `src/dopemux/mcp/launcher.py` `ensure_backend` already holds `instance_lock(target.runtime_dir)` around `lifecycle("start", ...)` → it MUST pass `hold_instance_lock=False` (otherwise every launcher start deadlocks). `ensure_orchestrator` calls `lifecycle("start")` under `reserved_port_lock(TO_PORT)` and the reaper never touches the orchestrator → pass `hold_instance_lock=False` there too (leave its lock order alone). The CLI sites (`src/dopemux/commands/mcp_commands.py` lines ~172 and ~507, which you do not own) keep the default → serialized. `grep -rn 'run_lifecycle(\|lifecycle(' src/dopemux` and account for every caller in your report.
- Locks held at the moment the new acquisition happens: none on the CLI path (then registry lock inside `_start_services`/`_stop_services`), so the order instance → registry holds. Confirm no path takes registry → instance or instance → reserved.
Tests (`tests/unit/test_mcp_lifecycle.py`; read how it drives `run_lifecycle` with fakes first): `start` and `restart` acquire `launch.lock` of the right runtime dir exactly once (monkeypatch `lifecycle.instance_lock` with a recording context manager, or hold the lock from a helper subprocess and assert the CLI path blocks/`LockBusy` semantics — recording is enough); `hold_instance_lock=False` skips it; dry runs skip it. `tests/unit/test_mcp_launcher.py`: the fake `lifecycle` callables must accept the new kwarg; assert `ensure_backend` and `ensure_orchestrator` pass `hold_instance_lock=False`.

## B3. Codex P2 — crashed launchers never become idle candidates

`reap.py` `plan_reap` (line ~430): `live_attachments(runtime_dir, prune=False)` then `_last_detach_age`. When a worktree's only launcher died by SIGKILL or host crash, its dead `attached/<pid>` record remains and `last_detach` does not exist, so `age is None` and the instance is skipped forever while the checkout exists; the pruning that would create `last_detach` runs only inside `_reap_one` (`live_attachments(prune=True)`), which the candidate never reaches.

Required: derive idle eligibility in planning from dead attachment timestamps WITHOUT mutating anything. Add `_effective_last_detach(runtime_dir) -> Optional[float]` = the max of `last_detach`'s mtime (if present) and the newest dead attach record's mtime (dead = `not _pid_alive(pid)`; records whose name is not a positive integer are ignored, as `live_attachments` does); no unlink, no stamp. Unreadable `attached/` (OSError other than FileNotFoundError) → `None` (planning already treats an unreadable dir as attached via `live_attachments` returning 1, so this is belt and braces). Use it in `plan_reap`'s idle computation; `_still_eligible` runs under the lock after `live_attachments(prune=True)` has stamped `last_detach`, so it may keep `_last_detach_age` or use the new helper for consistency (state which and why). Tests: a runtime dir with one dead attach record (use a pid from a finished subprocess, e.g. `subprocess.run(["true"])`'s pid, or monkeypatch `_pid_alive`) older than `idle_s` and no `last_detach` → `plan_reap` yields an `idle` candidate AND the dry run leaves `attached/` and the absence of `last_detach` untouched; then `apply_reap` under the lock prunes and reaps it; a dead record younger than `idle_s` → no candidate; `last_detach` newer than the dead record wins.

## B4. Acceptance finding 2 — a build-only launch leaves an orphan runtime dir reap never sees

`launcher.py` `_build_image_if_missing` (line ~413) writes `build-<service>.pid`, `build.log`, the compose build override and `mcp.env` into `target.runtime_dir` and raises `LAUNCH_IMAGE_BUILDING` before `lifecycle("start")` ever creates a registry entry. `plan_reap` joins candidates on registry entries (`_entry_for` → `None` → skip), so once that worktree is removed the dir stays forever (`dopemux-mvp-2271` on the owner's host; no containers, no ports, so Low).

Ruled design:
- The launcher writes a marker `<runtime_dir>/instance.json` = `{"project_id", "worktree_hash", "worktree_root", "project_root", "written_at"}` atomically (tmp + `os.replace`, 0600) at attach time, under the instance lock it already holds there (`launch()`, around line 791: `with instance_lock(target.runtime_dir): record = attach(target.runtime_dir)`), when the file is missing or its fields differ. Writing is best effort: an `OSError` prints one stderr line and never refuses the launch. Fields come from `target.identity` / `target` (check `LaunchTarget` for the exact attribute names).
- `plan_reap` gains a third candidate source: each directory directly under `registry.path.parent` that holds `instance.json`, whose `(project_id, worktree_hash)` is not in `seen_pairs` and has no registry entry (`_entry_for` is `None`), and whose marker fields are well-formed (`_SAFE_HASH` for the hash; `runtime_dir_for_paths(project_root=marker.project_root, worktree_hash=..., registry_path=registry.path) == that dir`, else ignore it: not ours). It becomes a state-only candidate (`container_ids=[]`, `services=[]`, reason `worktree_missing`) only when ALL hold: `_worktree_gone(worktree_root)`, `live_attachments(prune=False) == 0`, and no live detached build (`build-*.pid` whose pid is alive and whose file is younger than `dr.build_timeout_secs()`; implement the check in `reap.py`, do not import `launcher` into `reap` — `launcher` imports `reap`). RULING: dir-only candidates reap on `worktree_missing` only, never on idle (a container-less dir costs nothing; an idle rule would delete build logs of live worktrees). Malformed or unreadable markers are ignored silently; dirs without a marker (legacy, like the host's `dopemux-mvp-2271`) are not candidates.
- `_reap_one` must handle such a candidate: `_runtime_dir_is_ours` passes, instance lock, no containers → `_stop_and_remove` must make no docker call with an empty list (verify; adjust if it would), `_release_state` finds no leases/entries, rmtree. `ReapCandidate.to_dict` should let a reader tell this case apart (e.g. the existing `state_only` flag is enough if it is already serialized; check).
Tests (`tests/unit/test_mcp_launcher.py`, `tests/unit/test_mcp_reap.py`): the build-only refusal path leaves `instance.json` with the right fields (and a second launch does not rewrite an identical marker); a runtime dir with a marker and a missing worktree → `plan_reap` lists a state-only `worktree_missing` candidate and `apply_reap` removes the dir; the same with a live `build-*.pid` → not listed; marker whose `runtime_dir_for_paths` does not match the dir → not listed; existing worktree → not listed; no marker → not listed.
