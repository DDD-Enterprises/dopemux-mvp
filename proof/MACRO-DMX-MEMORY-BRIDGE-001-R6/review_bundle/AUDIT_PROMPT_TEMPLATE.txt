INTENT (what the change claims to do)
A new Claude Code function-hook mod ("mod") named dopemux-memory-bridge under plugins/dopemux-memory-bridge/ (plugin.json, hooks/hooks.json naming one module, hooks/register.tsx, hooks/register.test.ts, README.md) plus a how-to at docs/02-how-to/memory-bridge.md. It claims to:
(a) LOCAL OUTBOX: after each finished main-loop turn, on compaction and at session end, append a derived digest row (goal = first 160 characters of the user's prompt, relative file paths touched by Edit/Write/NotebookEdit, up to 3 marker-detected decisions, completed TodoWrite titles) to a per-session JSONL ring file `<repo-root>/.dopemux/memory-bridge/outbox-<sessionId>.jsonl` (plus an alternate generation file), written only when `<repo-root>/.dopemux` already exists (never created); otherwise rows live in memory and the plugin's `$.store` (a per-plugin JSON file that Claude Code keeps on disk in the user's config directory across sessions; the mod keeps the newest 3 sessions there, at most 256 KiB each). Caps: 1 MiB per file, 8 KB per row. Decisions are captured only from an answer line starting `Decision:` or `DECISION:` and stay local. All strings are redacted by an in-module redactor and capped. No raw prompt, tool output or answer text is stored.
(b) STATUS LINE: `$.ui.status` shows how many replayable rows wait (`📮 N pending`, `📮 clear`, `📮 memory-only`, `⚠ outbox write failed`, `⚠ N undeliverable`, `+N dropped`).
(c) WELCOME-BACK BAND: after `idleMinutes` (default 30, range 5-1440) without a prompt or finished turn, one line above the prompt: `Welcome back - you were on <goal> - last decision <decision> - <n> uncommitted files` (count from `git status --porcelain` via `$.process.run`, omitted when unavailable). The hook wraps what `next(e)` returns instead of replacing it and shows nothing when a survey is open.
(d) LEDGER REPLAY: completed todos and notes entered with the mod's only slash command `/bridge-note <text>` (menu description: 'Queue a note for the capture ledger') are replayed to the LOCAL capture ledger by running `$.process.run(["dopemux","capture","emit","--event",<json>,"--mode","plugin","--repo-root",<root>], {timeoutMs: 15000})`: serial, at most 3 rows per 60 s tick, a row becomes `sent` only after exit code 0, five failed attempts make it `dead`, a call that never ran (no `$.process`) does not count as an attempt. Only the event types task.completed and manual.memory_store are emitted.
(e) NOT BUILT, on purpose (the how-to must say so): a session-start recap; the event decision.logged; replay to the dope-memory REST service; any ConPort read or write.
(e2) RELAY (added in R4): at session start, a session copies into its own outbox the undelivered task and note rows of earlier sessions of the same repo whose outbox file has not changed for at least 10 minutes and whose rows are at most 7 days old, at most 50 rows per start, oldest first; each copy keeps the original row id, timestamp, session_id and attempts, gets `adopted_from` (the earlier file's key), and is delivered by the same replay; the earlier file is never written; rows of a file changed in the last 10 minutes (a live session) are left to that session; ids that are sent or dead in any file read or already in this process's rings are not adopted; adoption runs once per session start, not on /clear, and never in memory-only mode; turn, compact and end rows are never adopted. `📮 N pending` counts only replayable rows this process will deliver, including relayed ones. Decision capture scans only the first 200,000 characters of an answer.
(e3) FILE KEY (added in R5): an outbox file and `$.store` key is the session id itself when the id is 1-80 characters of letters, digits, `_` and `-` (Claude Code's own ids); any other id (other characters, empty, or longer than 80) gets the key `<prefix>~<h>`, where `<prefix>` is the id with every other character replaced by `_`, cut to 56 characters (possibly empty), and `<h>` is 16 hex digits from two synchronous 32-bit FNV-1a passes over the whole id (the second over the id prefixed by a NUL character). Keys of the first form never contain `~`, so the forms cannot meet; existing files keyed by ordinary ids keep their names.
(e4) THIS REVISION (R6) changes no mod code: `hooks/register.tsx` is byte-identical to the R5 audited head. It changes (1) the test file only: a helper `untilWritten` makes the file-key tests wait for the asynchronous outbox write before asserting (before, they asserted right after the mock clock's settle(), which could run before a `crypto.subtle.digest` of an input of 64 bytes or more had finished, so some parallel runs failed); (2) the README and the how-to, for the review findings C1-C3 below.
