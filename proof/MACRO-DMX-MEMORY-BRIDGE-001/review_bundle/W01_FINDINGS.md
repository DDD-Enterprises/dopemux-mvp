## 4. Q3 Outbox

- Location: the API has no plugin data dir (`$.plugin` is `{ name, root }`, d.ts:2355-2364; `root` is the mod's own source folder, do not write there). Proposed: `<repo-root>/.dopemux/memory-bridge/outbox-<sessionId>.jsonl`, with `<repo-root>` found by the same upward walk as `capture_client.py:76-87` (nearest `.git` or `.dopemux`; do not use `$.session.repo().root`, which is the MAIN worktree root, d.ts:12066). Write only if `<repo-root>/.dopemux` already exists (`$.fs.exists`), else keep the outbox in memory plus `$.store` (4 MiB total, shared by all sessions of the plugin; cross-process write semantics UNKNOWN).
- Gitignore (confirmed, not assumed): `.gitignore:140` and `.gitignore:299` are both `.dopemux/`. `git check-ignore -v .dopemux/memory-bridge/outbox-x.jsonl` prints `.gitignore:299:.dopemux/` (exit 0); `.dopemux/chronicle.sqlite` the same. Proven for THIS repo only; other repos (adOps, dNh_CRM) are UNKNOWN, hence the exists-guard above.
- Writing: `$.fs.write(path, text)` creates parent directories and replaces the whole file (d.ts:3333-3338); relative paths resolve under the session cwd, so pass an absolute path. "where one may go is an `fs.*` hook's to say" (d.ts:3307): another plugin's `fs.*` hook could veto; treat a rejected write as a soft failure.
- Rotation without rename or delete: there is neither (fs surface list, d.ts:3312-3440). Use a rewrite-in-place ring: keep rows in memory, serialize to the file after each change, drop the oldest rows until the serialized size is at most 1 MiB. Emptied or drained files are overwritten with an empty string, never removed; orphan files from dead sessions are adopted only when their `mtime` is over 24 h old (`$.fs.list` gives `mtimeMs`).
- Race: `fs.write` is read-modify-write at the mod level (no append, no lock). Two sessions on one repo writing ONE shared file lose rows. Recommended: one file per session id (`$.session.id()`, d.ts:2855), single writer, and serialize in-session writers through one promise chain (hooks run concurrently).
- Size cap: reads reject over 4 MiB (d.ts:3317) and writes too (d.ts:3309). Cap each file at 1 MiB (4x margin) and each row at 8 KB.
- Torn writes: atomicity of `fs.write` is not stated: UNKNOWN. Mitigate with two alternating generation files carrying a monotonic sequence, reader takes the highest valid, and tolerant JSONL parsing.

Verdict: GO_REDUCED. Bucket PASS (declaration + `git check-ignore` observed).
