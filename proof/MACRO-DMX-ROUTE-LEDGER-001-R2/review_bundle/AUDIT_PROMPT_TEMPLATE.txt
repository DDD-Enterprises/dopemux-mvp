INTENT (what the change claims to do)
A new READ-ONLY Claude Code function-hook mod ("mod") under plugins/dopemux-route-ledger/ (plugin.json, hooks/hooks.json, hooks/register.tsx, hooks/register.test.ts, receipt.schema.json, README.md) plus a how-to (docs/02-how-to/route-ledger.md). It records delegation and advisor receipts for the people who supervise multi-agent work:
- On `tool.call` for the `Agent` tool it records the REQUESTED `model` alias (and effort, subagent type, a description truncated to 80 characters; never the prompt) and warns by toast, config-controlled (`unpinnedAgent`: warn|off), when no model is pinned (a `fork` with no model inherits and is not unpinned). The hook changes nothing and must call `next(e)` exactly once with `e` unchanged on every path.
- `agent.spawn` is used only to join `tool_use_id` to the spawned `agentId` and resolved model.
- On `turn.step` (a streaming event: `async function*` with `yield*`) it records the requested model of the step, the OBSERVED model from `usage.model`, token counts, and counts `serverToolUses` named `advisor`, deduplicated by the server-tool-use `id`, split main loop versus agent loop. The mod can COUNT advisor calls and cannot block, refuse or rewrite them.
- It writes JSONL receipts under a receipt directory (default `.control-tower/state/route-ledger`, used only if `.control-tower/state` exists; an explicit directory is created on first write; a `..` segment disables receipts). `$.fs.write` replaces a whole file and there is no append, so the mod keeps an in-memory segment and rewrites it whole through a serialized promise chain, rolling to a new segment file at a receipt cap or about 3.5 MB. Tallies are rebuilt from the session's own receipt files after a hot reload (no `$.state`).
- Receipts carry `binding_fields`, a partial mapping a supervisor can merge into a GEC v2 ExecutionBinding before running `ct bind-record`. The mod never runs `ct` and a receipt is not a valid binding; `response_claimed_model` is the API-reported model, not provider attestation; effort observed and provider attestation are always UNKNOWN.
- Surface: a status segment (e.g. `agents S×4 H×2 · advisor 1`, ` · ledger off`, ` · receipts ✗`, `advisor N/B ⚠`) redrawn debounced; toasts once when an advisor budget (`childAdvisorBudget` default 0, `sessionAdvisorBudget` default off) is exceeded; a command `/route-ledger` (canonical) with `/route` as a best-effort alias, each registered with its own `.catch`, printing a table of requested versus observed model per loop and advisor counts, with a `receipts` argument.
- Constraints: no `$.process`, no `$.http`, no `$.model`, no `$.state`/`$.store`, no prompt hooks, no `$.agent.spawn`; no write outside the receipt directory; no hook may throw into the host; `session.end` with reason `clear` is not an end.
