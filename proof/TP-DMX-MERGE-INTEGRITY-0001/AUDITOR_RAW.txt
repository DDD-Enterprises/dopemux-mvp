### Executive Summary & Verdict
The proposed design in [adr-dmx-merge-integrity-agent-patch-admission.md](file:///Users/hue/code/dopemux-merge-integrity-0001/docs/90-adr/adr-dmx-merge-integrity-agent-patch-admission.md) and [merge-integrity-architecture.md](file:///Users/hue/code/dopemux-merge-integrity-0001/docs/03-reference/merge-integrity/merge-integrity-architecture.md) provides a comprehensive, defense-in-depth framework for merge integrity. It successfully addresses the root causes of stale-branch clobbers (#932, #1025) and establishes strict, tree-bound candidate validations. However, it relies on several critical implementation assumptions regarding GitHub Action runner security and operational policies, warranting a verdict of **`PASS_WITH_RISKS`**.

---

### Findings on the 14 Design Challenges

1. **Blocking PRs #932 and #1025**: **PASS**. The design replaces the deletion-blind `--diff-filter=ACMR` with complete deletion-aware Git object enumeration. Because the deletions affect protected surfaces (`src/dopemux/mcp/**` and `docker/mcp-servers-source/conport/migrations/conport_migration_gate.py`), and the Change Intent Registry for these PRs would not explicitly permit such actions, the sanitizer blocks candidate construction, preventing merge.
2. **PR #720 Conflict Honesty**: **PASS**. The design honestly documents that current repository evidence does not support the stale-branch clobber narrative for #720 (which only modified a single UI file). The incident is categorized as `CONFLICTING`/`UNKNOWN` in the [INCIDENT_MATRIX.json](file:///Users/hue/code/dopemux-merge-integrity-0001/proof/TP-DMX-MERGE-INTEGRITY-0001/INCIDENT_MATRIX.json) and fails closed.
3. **Legitimate Mass Deletion Gates**: **PASS**. Explicit authorization (`mass_deletion_intent`) in the Change Intent Registry is required alongside protected-surface review. However, the exact mechanics of these "additional gates" are left open in the architecture.
4. **PR #1038 Canary Processing**: **PASS**. The design successfully classifies PR #1038 as `agent_palette_jules` based on physical file markers (`.Jules/*`) rather than PR titles or branch names. It is blocked due to unresolved review threads and missing proof.
5. **Authority Leakage Prevention**: **PASS**. The design rejects advisory UI text, labels, branches, and worktree hygiene as authorization. Proof is cryptographically bound to the exact candidate tree. However, a risk of workflow execution compromise exists if validations run on the untrusted PR branch (see risks below).
6. **Race Condition Avoidance**: **PASS**. Expected-head validation invalidates the readiness state if any base/head commits, check statuses, reviews, threads, or policy labels change. Specifying the expected head SHA at the merge API call resolves the TOCTOU race for code pushes.
7. **Self-Reference & Stale-Proof**: **PASS**. The final gate excludes its own check status from the list of checks it waits for, avoiding event-loop deadlock. Stale proof is eliminated because all proofs are bound to the exact head SHA, tree SHA, and diff hash. Re-baselining main triggers a candidate rebuild, invalidating stale proof.
8. **Pagination & Patch-Size Limits**: **PASS**. The design falls back to local git object enumeration to bypass GitHub's 20,000-line patch endpoint limit (which failed for #1025) and enforces completeness checks (`HARVEST_INCOMPLETE`) to block on truncated API yields.
9. **Required-Check Deadlocks**: **PASS**. By declaring required checks in static repository policies rather than dynamically parsing GitHub rulesets, the final gate avoids waiting on itself.
10. **Solo-Operator Deadlock Avoidance**: **PASS**. A formalized, recorded, scoped, and time-bound supervisor override contract linked to the exact candidate SHA is defined to allow solo maintainers to progress securely.
11. **Unbounded Destructive Permissions**: **PASS**. The transactional merge executor has a restricted write scope. Automatic broad reverts are explicitly banned in favor of post-merge sentinels that freeze/report.
12. **Read-Only PR Steward**: **PASS**. The PR Steward is strictly read-only and divided into an early intake harvester and a final readiness evaluator.
13. **Bounded Patch Sanitization**: **PASS**. The Candidate Sanitizer applies only authorized patch hunks onto a fresh checkout of `main` instead of importing the untrusted branch's tree.
14. **Heuristics as Secondary Signals**: **PASS**. The design rejects heuristic thresholds (like deletion lines or file count) as authorization mechanisms, keeping them strictly as risk flags.

### Required Fixes
1. **Runner Environment Isolation**: The implementation phase *must* enforce that candidate construction, validation, and final readiness checking run in a privileged, read-only workflow context (such as a `workflow_run` event or a separate trusted supervisor service). They must *never* execute inside the standard `pull_request` context of the untrusted PR branch, as a malicious agent could modify the workflow YAML files to bypass or hijack the gates.
2. **Define Mass-Deletion Gates**: Explicitly detail the "additional gates" for mass-deletion authorization (e.g., requiring a specific cryptographically signed multi-signature override or dual-operator approval) before implementing [implementation-series-plan.md](file:///Users/hue/code/dopemux-merge-integrity-0001/docs/03-reference/merge-integrity/implementation-series-plan.md) packet `TP-DMX-MERGE-INTEGRITY-0003`.

---

### Accepted Risks
1. **Same-File Conflict Friction**: Because the Candidate Sanitizer applies patches to current `main` and blocks on any same-file conflicts, concurrent changes to the same file will frequently require manual re-baselining or registry updates. This operational friction is accepted in exchange for merge safety.
2. **Review State TOCTOU**: Specifying the expected head SHA during the merge API call prevents concurrent commits, but non-commit state changes (such as a developer resolving/unresolving a comment thread) could theoretically occur in the split-second window between the readiness re-check and merge execution.

---

### Residual Uncertainty
- **Merge Queue Interoperability**: The behavior of GitHub Merge Queues and their tree-SHA generation during parallel merge sequences remains an implementation-time uncertainty. It must be validated during packet `TP-DMX-MERGE-INTEGRITY-0006` to ensure it does not break the expected-head enforcement model.
