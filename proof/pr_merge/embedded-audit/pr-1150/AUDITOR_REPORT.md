  - **Regex is too narrow.** `_FLEET_START_RE = r"docker[- ]compose(?:\s+-f\s+\S+)*\s+up\b"` only tolerates repeated `-f <file>` flags between `compose` and `up`.     - `scripts/compose_nuke.sh:35` — `docker compose -p "$PROJECT" -f compose.yml up -d --remove-orphans --force-recreate`.
    Neither file is in the test's `_ALLOWLIST`, and neither is caught by the regex. Both remain fully live legacy fleet-launch paths after this PR merges.
  - **Structural blind spot for non-literal commands.** `src/dopemux/cli.py:3728-3801` (`_start_mcp_servers_with_progress`, called from `dopemux init`'s default startup flow at `cli.py:2433` — "Start MCP servers by default (ADHD-optimized experience)") builds `cmd = ["docker", "compose"] + compose_files + [..., "up", "-d", "--remove-orphans"]` as a Python list and runs it via `subprocess.Popen`. This is arguably the single most-used fleet-start code path in the whole CLI, it bypasses `dopemux mcp` entirely, and it is structurally invisible to a line-based regex scan since the literal string never appears contiguously in source. `src/dopemux/cli.py` is untouched by this PR (not in the diff) and not flagged anywhere as a known gap.
