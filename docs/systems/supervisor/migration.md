# Adopt a local supervisor candidate

1. Obtain exact owner approval for the candidate subject, paths, scope, permissions,
   deadlines, repair attempts, spend and current canonical packets/ExecutionBindings.
   A schema-valid portable v2 projection alone cannot authorize migration or execution.
2. Keep source, private state/returns and synthetic projects disjoint. Verify the current
   UID, canonical roots, private directory modes and original candidate/source hashes.
3. Run focused offline verification against the frozen subject. Validate v1 compatibility,
   atomic admission fault injection, forged/stale/revoked owner rejection, second-process
   local denial and publication isolation. Review collected/skipped/failed counts and logs.
4. Commission only the separately authorized independent review. Preserve prior FAILs,
   consumed review attempts, unknown effects and old deadlines. Passing local fixtures
   does not reset those histories or constitute native acceptance.
5. Integrate only after remaining owner/review gates. No installer, automatic startup,
   canonical state migration, cloud ACK bridge or live provider route is included here.

## Existing journals

Do not edit historical journal rows to appear admitted or replenish a grant. Identical
re-admission preserves original route IDs on already admitted works and keeps all counters.
New work uses mandate-qualified route identities, preventing unrelated manifests sharing
a route label from conflicting merely because their deadlines differ. Legacy incomplete
admissions hold their affected project. Their original limits remain unchanged.

Returns now use `records/` with explicit local semantics. Legacy `acks/` files do not
settle delivery and must not be renamed into records. A real Native or Master receiver
requires future owner-bound cross-domain provenance; there is no automatic conversion.

An existing permissive state/return root is rejected. Establish approved private custody
before use; the runtime does not silently chmod, adopt or migrate such a directory.
Never copy active state under a second coordinator or split physical custody across journals.

## Parallel documentation and runtime dependencies

The separately owned W23 S2/S3 documentation remains its own source subject. This S1
candidate adds supervisor/admission pages and instruction pointers, without copying or
asserting acceptance of that work. Structural inventory counts are not live deployment
counts or completion of the full architecture documentation campaign.

W04 must repair PM transition success/version/SYNCED handling and the synchronous caller
of async ConPort progress before those paths can provide trustworthy acceptance evidence.
These are runtime dependencies, not wording fixes. This wave changes no PM/TO/MCP service
state or adapter source. W02/W03/W06/W08/W09 retain the deferred custody, control, closure,
evidence, drift, ACK and queue work listed in the [adoption record](../../04-explanation/architecture/full-system-r2/adoption.md).

## Rollback

Stop only owned processes and prove closure before reverting an installed source subject.
Use exact file ownership and hashes; preserve journals, owner history and evidence. Reverting
source does not undo external or unknown effects. No broad reset/clean, active-worktree deletion,
canonical ledger rewrite, automatic retry or deadline extension is authorized by rollback.
