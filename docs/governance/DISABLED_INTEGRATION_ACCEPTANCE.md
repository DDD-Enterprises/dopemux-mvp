# Disabled Governance integration acceptance

## Acceptance contract

Acceptance covers only the disabled integration package, its regressions,
documentation and two explicit setuptools package entries. The entrypoint must
remain unconditionally DISABLED/HELD. No callback, ambient flag, API authority,
journal, fixture execution or live service is enabled.

An attributable result must identify source and dependency pins, Python and
backend versions, sandbox profile, commands, exits, test counts, failures,
artifact hashes, imported origins and owned-process closure. In particular:

1. Verify the eight-path delta and unchanged entrypoint. Preserve repository
   pytest configuration and root conftest; account for their baseline imports.
2. Build one actual wheel offline without installation or dependency resolution.
   Inspect its manifest and verify the intended Governance module bytes.
3. Stage the wheel into an owned directory without installing it. Prove package
   imports and bounded help/status/refusal checks originate there. Run applicable
   original regressions with their unchanged assertions and recorded context.
4. Keep network, shared-repository access and frozen-source writes denied;
   exclude editable/startup mappings and plugin autoload. Any needed explicit
   plugin and baseline behavior must be recorded, not silently replaced.

Source-only tests, static checks and staged-source smoke are not wheel or
artifact-origin acceptance. A successful narrow artifact batch does not prove
whole-project, hosted CI, production or installation readiness. Changed bytes
are a new frozen subject and do not inherit an independent verdict.
