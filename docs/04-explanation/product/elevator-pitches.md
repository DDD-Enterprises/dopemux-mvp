# Elevator Pitches

These pitches are grounded in the current repo docs and inspected runtime
boundaries. They are not permission to claim production readiness, unified PM,
unified memory, unsupervised operation, or unified agent authority.

## One Sentence

Dopemux is an operator control surface that coordinates split-authority
development workflows while preserving which system owns each slice of truth.

## Thirty Seconds

Dopemux gives an operator a control surface for development work that spans
execution handoff, PM workflow, structured context, chronicle history, derived
retrieval, bridge routing, operator support, and repo-truth audit. The
important part is that it does not flatten those systems into one assistant. It
keeps Leantime, task-orchestrator, ConPort, dope-memory, dope-context,
dopecon-bridge, ADHD Engine, and Repo Truth Extractor in their own authority
lanes.

## Two Minutes

Development-control work often crosses too many tools: local startup, task
execution, PM metadata, workflow transitions, decisions, progress, chronicle
history, derived retrieval, service routing, and repo audit. Dopemux is the
operator-facing control surface for coordinating that stack.

The repo-grounded architecture is split-authority. `dopemux` owns operator
control. `dopetask` owns execution after handoff. Leantime owns passive PM
metadata. task-orchestrator owns workflow transitions. ConPort owns structured
decisions and progress. dope-memory owns chronicle receipts. dope-context owns
derived retrieval. dopecon-bridge proxies and routes; it does not become the
truth owner. ADHD Engine supports the operator. Repo Truth Extractor produces
evidence artifacts for the audit trail.

That makes Dopemux useful for operators who need coordination and proof, not a
clean story that hides drift. If runtime evidence is missing, Dopemux docs keep
the claim as UNKNOWN or NEEDS_REPO_VERIFICATION.

## Guardrail Pitch

Dopemux is not a monolithic assistant. It is a control surface for a
multi-system workspace where source truth, mirrors, proxies, derived retrieval,
and evidence artifacts remain labeled.

Dopemux coordinates work across authority lanes. It does not collapse those
lanes into one owner.

## Anti-Pitches

Do not use these:

- "One assistant owns all PM, memory, execution, and retrieval."
- "A bridge-centric PM platform."
- "A production-ready unsupervised development company."
- "A unified memory layer."
- "An agent runtime with one proven owner."

Each of those overclaims beyond current repo evidence.
