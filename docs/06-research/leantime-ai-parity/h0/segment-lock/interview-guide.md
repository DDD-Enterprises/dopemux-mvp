# Interview Guide

Duration target: 30–45 minutes. Product-neutral wording. Do not pitch Leantime or OpenProject as preferred.

## Opening

1. Confirm consent and redaction.
2. Role, team size, delivery context (no employer required if sensitive).
3. Current PM / work-tracking tools (names OK; no credentials).

## Buyer track (if applicable)

1. Who decides tooling budget or self-host operations?
2. Last tool switch — trigger, veto criteria, must-haves.
3. Rank importance (1–5): auditability, self-host control, AI assistance, cost predictability, integration depth, ADHD/cognitive load support, mobile/admin ops.
4. Hard non-starters.

## User track

1. Walk through a high-frequency workflow end-to-end (steps, handoffs, tools).
2. Top three pain points by frequency and severity.
3. Admin vs maker tasks; cognitive-load moments.
4. Accessibility or mobile constraints observed.

## Workflow candidates (probe, do not force)

Ask which of these (or others) are weekly critical:

- Backlog triage and prioritization
- Sprint/iteration planning and commitment
- Status reporting / stakeholder visibility
- Cross-team dependency tracking
- Incident / interrupt handling vs planned work
- Release / milestone gating
- Personal task capture under cognitive load

Capture participant-proposed workflows with equal weight.

## Closing

1. Anything we assumed wrong?
2. Permission to follow up for clarification (yes/no).
3. Withdrawal reminder.

## Post-session redaction checklist

- [ ] Opaque ID assigned
- [ ] Consent recorded
- [ ] Buyer/user/mixed class set
- [ ] Evidence grade A/B/C assigned
- [ ] Contradictions tagged
- [ ] No PII in summary lines
