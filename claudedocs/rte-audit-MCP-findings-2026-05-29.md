## PART 1 — In-tree orchestration library (`src/dopemux/mcp/`)

Scope: roles.py, gate.py, provision.py, server_manager.py, session_manager.py, token_manager.py, instance_overlay.py, resolver.py, registry.py. **Enforcement point (broker.py) was OUT of scope — see MCP1-01.**

- **[MCP1-01] HIGH — Authority model is split: audited library defines roles but does not enforce them.** roles.py:64,87-92 are data only; the allow/deny decision lives in broker.py:663,266 (out of scope). No `is_tool_allowed`/`filter_tools`/deny logic in the nine in-scope files. A reader of roles.py could wrongly conclude RBAC is enforced. **Follow-up required:** confirm broker.py consults `role.all_possible_tools` and rejects non-members + fails closed on unknown role. `grep -n "all_possible_tools\|default_tools\|deny\|forbidden" src/dopemux/mcp/broker.py`
- **[MCP1-02] HIGH — Discovery gate fails OPEN for env-var and global-fallback servers.** gate.py:48,73-83 — only `provenance == "repo_profile"` servers can set `passed=False`; env_var/global_fallback servers never block even if unreachable or failing glob validation. Combined with resolver.py:56-64 (any `DOPMUX_*_URL` env var → registered server, provenance `env_var`), one env var introduces an endpoint the Phase-0 gate will never block.
- **[MCP1-03] MED — Gate validates reachability/tool-presence, not authorization; `handshake_required` suppresses all glob checks.** gate.py:55-74 — a reachable-but-unauthenticated server passes glob validation with zero tools confirmed; a required tool can be absent and the run still PASSes.
- **[MCP1-04] HIGH — Child MCP processes inherit the full parent environment (all secrets); HTTP auth headers built from env with no scoping.** server_manager.py:446-461 (`full_env = os.environ.copy()` → Popen), :483-494 (`Bearer {os.getenv(api_key_env)}`). Every stdio server spawned with ANTHROPIC/OPENAI/VOYAGE/GROQ keys + DB creds. A compromised server binary reads every host secret. Most material secret issue in scope.
- **[MCP1-05] MED — Session state in fixed world-accessible `/tmp` path, no per-user/instance isolation, no path-traversal guard.** session_manager.py:206-207 (`/tmp/metamcp_sessions`, default umask), :730 writes `{session_id}.json` (a `session_id` of `../foo` escapes the dir; `from_dict` deserializes attacker-controlled fields). Token DB `/tmp/metamcp_tokens.db` (token_manager.py:151). Local info-disclosure + context-injection / arbitrary-path write.
- **[MCP1-06] MED — Instance port allocation collides; container names collapse to shared defaults.** instance_overlay.py:34-37 maps first char of instance_id to base port → `"Alpha"` and `"Auth"` both → 3000 → identical port map; `instance_id in (None,"A")` collapse to shared container names (:87-88,120,129); non-letter IDs → md5-mod-30 (only 30 buckets). Breaks workspace-scoping isolation ConPort/Serena rely on.
- **[MCP1-07] MED — `check_budget_availability` defined but never called in scope; budget enforcement advisory.** token_manager.py:349-367 (no in-scope caller), :292-343 `record_usage` only adds, never blocks. `hard_cap`/`EXCEEDED` exist but nothing acts on them here. Cost/DoS if broker doesn't gate dispatch on it.
- **[MCP1-08] LOW — Provisioner trusts on-disk stack source; can rename/delete existing `docker/mcp-servers` dir.** provision.py:97-104 (renames real dir to `.bak`, `rmtree`s prior `.bak`), :27-80 source resolution has no integrity/version check. A planted `docker/mcp-servers-source/start-all-mcp-servers.sh` becomes the launched stack (supply-chain foothold, interacts with MCP1-04).
- **[MCP1-09] LOW — Dead `logger.error(...)` after `raise` across server_manager.py:262,431,535,584,665,707,748.** Re-raises without the intended log record → missing audit trail on tool-dispatch/server-start/health-check failures.
- **[MCP1-10] LOW — gate.py ConPort spelling-fallback is a no-op (botched find/replace).** gate.py:66-71 — `glob.startswith("conport_") or glob.startswith("conport_")` (identical operands); `glob.replace("conport_","conport_")` (self-replace). Intended `conport_`↔`conport-` fallback is inert; validation on a contract-sensitive surface is provably dead. Fails closed (false block) not open.

**Checked & NOT material:** token_manager.py SQL uses bound `?` params (no injection); resolver.py `allow_global` defaults False (fail-closed); registry.py Pydantic `extra="forbid"` + raises on missing/malformed (fail-closed). No secrets stored/logged/returned by token_manager or session_manager.

## PART 2 — Standalone servers

Scope: services/mcp-capture/server.py, services/mcp-integration-bridge/{kg_authority,kg_endpoints,main}.py, services/mcp-client/main.py, services/shared/mcp/{pal_client,response_budget}.py.

- **[MCP2-01] HIGH — KG authority middleware fails OPEN for any unlisted `/kg/*` path.** kg_authority.py:40-93 — only `/kg/health` + `/kg/decisions` rules; unmatched paths fall through to `call_next`. Per-endpoint protection is coincidental (real endpoints happen to start with `/kg/decisions`); a future `/kg/admin/*` or non-GET route without an in-handler check is unguarded. Real enforcement is scattered per-handler `if` blocks (kg_endpoints.py:93-96).
- **[MCP2-02] HIGH — PM plane not actually read-only; "authority" is a self-asserted unauthenticated `X-Source-Plane` header.** kg_authority.py:58, kg_endpoints.py:81,93-96 etc. — plane identity from client header, no signature/token/mTLS. Absent header short-circuits the check (`x_source_plane and ...`). Any client setting `X-Source-Plane: cognitive_plane` gets full access; wide-open CORS lets a browser origin set it too.
- **[MCP2-03] HIGH — `capture/emit` forwards an unvalidated event envelope into Chronicle ingestion.** server.py:99-114 — `event = arguments["event"]` passed verbatim; declared `inputSchema` (enum on `mode`, required `event_type`) not enforced by handler; `lane` passed untouched (client can self-assign a capture lane). Stored-injection vector if any consumer replays `payload`/`event_type` into a model/UI.
- **[MCP2-04] HIGH — Provider API keys as `os.getenv()` fallbacks in source (redacted now → probable git-history leak).** mcp-client/main.py:278-279 — `os.getenv('GEMINI_API_KEY', '<redacted>')`, `os.getenv('XAI_API_KEY', '<redacted>')`. Placeholder-in-default pattern signals real keys once committed; working-tree scrub does not remove from history. **Falsifying check (NOT_RUN, do not echo values):** `git log -p -- services/mcp-client/main.py | grep -iE 'AIza|xai-|sk-[A-Za-z0-9]'`. If found: rotate + scrub history (filter-repo/BFG).
- **[MCP2-05] MED — Internal DB/query exception strings echoed verbatim to HTTP clients.** main.py:1374,1400,1488,1503,1536 + kg_endpoints.py:121,162,213,272,326 (`detail=str(e)`). Leaks table/column/SQL structure to unauthenticated callers (CORS `*`). Author hardened two handlers (main.py:1626-1628, 968-970) but applied it inconsistently.
- **[MCP2-06] MED→HIGH — Debug endpoint returns Postgres connection string (with password) + Redis URL to any caller.** main.py:1680-1695 returns `POSTGRES_URL` (default embeds `dopemux:dopemux_password`, :62-65) with no auth/plane check; `host="0.0.0.0"` (:1701) + CORS `*`. If reachable off-host → CRIT. Most concrete live secret leak in the set.
- **[MCP2-07] MED — Wide-open CORS with credentials on a service exposing secret/debug endpoints.** main.py:1200-1206 (`allow_origins=["*"]`, `allow_credentials=True`, `allow_methods/headers=["*"]`). Amplifies MCP2-02 (header-only plane auth) and MCP2-06 (debug secret) into browser-reachable attacks. `allow_headers=["*"]` lets a malicious page set `X-Source-Plane`.
- **[MCP2-08] MED — mcp-client stdio transport: one-line read, no JSON-RPC id matching, no framing, no timeout.** mcp-client/main.py:82-100,121-189 — hardcoded ids 1/2/3, response id never checked vs request id, no read timeout, undrained stderr PIPE (deadlock risk). A server emitting a banner before the response desyncs the client → acts on wrong tool result.
- **[MCP2-09] OBS — Bridge passes bare SQL strings to `session.execute()` without `text()`; would raise on SQLAlchemy 2.x.** main.py:664-691,870-881,931-939,1551-1561; `text` not imported (:34). Confirms SQL is parameterized (closes injection concern) BUT next-tasks/dashboard paths likely non-functional/untested on SA 2.x (fail-closed → `[]`).
- **[MCP2-10] OBS — pal_client.py sends `Authorization: Bearer ""` when config lacks api_key; unreachable `logger.error` after every `raise`.** pal_client.py:20-26,59-143. No secret leaked (empty); error logging silently broken across all six methods.

**Cross-cutting:** KG REST surface is **read-only** (all `@router.get`); canonical KG writer is ConPort (out of scope), so no write-authority bypass exists *through these endpoints* — but read-confidentiality controls are fail-open + header-only. Capture/emit (MCP2-03) is the one unsanitized untrusted-content ingestion path. Bridge request bodies get Pydantic validation; gaps are capture/emit + wrong status codes.

**Highest priority:** MCP2-06 (live DB password, unauth, 0.0.0.0), MCP2-04 (probable secret-in-history), MCP1-04 (full-env leak to children), MCP1-02 / MCP2-01 / MCP2-02 (fail-open + header-only authority). **MCP1-01 leaves RBAC enforcement UNVERIFIED — broker.py follow-up needed.**
