## 1. FileEntry Dataclass — Complete Structure

**Location:** scripts/doc_audit_prescan.py, lines 169-180

```python
@dataclass
class FileEntry:
    rel_path: str                    # Relative path from repo root (e.g., "docs/README.md")
    size_bytes: int                  # File size in bytes
    extension: str                   # File extension, lowercase (e.g., ".md", ".py")
    authority_class: str = ""        # Assigned class: canonical|historical|operational|audit|template|generated|noise
    include: bool = True             # Whether file is included in corpus
    exclude_reason: str | None = None # Reason for exclusion (e.g., "binary_extension:.png", "size_exceeds_max")
    content_hash: str | None = None  # SHA256 hash of file content (computed for included files)
    directory_class: str = ""        # Top-level directory bucket (e.g., "docs", "scripts", "root")

    def to_dict(self) -> dict:       # Serializes to dict, filtering None values
        return {k: v for k, v in asdict(self).items() if v is not None}
```

### Data Computed Per File During walk_corpus():
1. **rel_path**: Computed from path.relative_to(repo_root)
2. **size_bytes**: From path.stat().st_size
3. **extension**: From path.suffix.lower()
4. **content_hash**: SHA256 computed via _sha256_file() for INCLUDED files only (line 282)
5. **directory_class**: Top-level directory extracted from path.parts[0] (line 289)
6. **exclude_reason**: Set during exclusion checks (binary, glob, size, json threshold, unknown ext)

## 11. Prescan Modes

**Three execution modes:**

1. **dry-run** (lines 884-886):
   - Runs heuristic classifier only
   - Writes manifests (corpus_stats.json, corpus_manifest.json)
   - NO Grok calls, NO payload packaging
   - Fast (~seconds for 1000 files)

2. **direct** (lines 888-897):
   - Packages payload (audit_payload.md)
   - Calls Grok API directly via openai client
   - Writes grok_response.json with classifications
   - Returns parsed response with confidence scores

3. **handoff** (lines 899-902):
   - Packages payload
   - Builds complete handoff_bundle/ with routing, manifest, checksums
   - Does NOT call Grok (leaves that to recipient)
   - Provides instructions.md for 3 execution paths

## 13. Gap Analysis: Integration with Extraction Pipeline

### What's Present:
- ✅ FileEntry with content_hash (SHA256)
- ✅ Authority classification (heuristic + LLM)
- ✅ corpus_manifest.json with all file metadata
- ✅ corpus_stats.json with aggregate breakdowns
- ✅ WizardState captures corpus_manifest for phase routing

### What's Missing from Pipeline:
- ❌ **No Git History Integration**: No git log, git blame, commit frequency analysis
- ❌ **No Dedup Detection**: No content similarity/SSDeep/fuzzy matching
- ❌ **No Drift Detection**: No change frequency tracking or volatile file detection
- ❌ **No Phase Routing Policy**: How files flow from corpus_manifest → phases A-Z
- ❌ **No History Extraction**: No retention of historical evolution within extraction

### Potential Enhancement Points:
1. corpus_manifest.json could include git_info (last_commit, change_frequency)
2. FileEntry.content_hash could enable content dedup in phases
3. Authority class should influence phase partitioning (canonical→D, operational→E, etc.)
4. Handoff bundle could preserve git history snapshot for replayability
