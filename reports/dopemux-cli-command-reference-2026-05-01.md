## Expanded Boundary Notes

- `dopemux mcp` and `dopemux servers` are Docker Compose control surfaces. After remediation, targeted service arguments are validated against `compose.yml` and subprocess calls use argv lists instead of shell interpolation.
- `dopemux routing api/direct` mutate `~/.dopemux/routing.yaml` through deterministic YAML serialization and preserve existing config fields. Service restart/reload is delegated to `LaunchdServiceManager` when requested.
- `dopemux code` is a boundary to the repo-local `services/genetic_agent` package. Missing dependencies now fail with a nonzero Click error instead of logging success-path exit status.
- `dopemux profile copy/edit/delete/current` are backed by the real profile-management callbacks in `src/dopemux/profile_commands.py`; they are no longer placeholder commands.
- `dopemux pr-merge` is a Click-to-argparse delegate. The authoritative parser and behavior live in `src/dopemux_pr_merge_specialist/cli.py`.
- `dopemux kernel` still uses `scripts/taskx`, which delegates to `scripts/dopetask`; TaskX naming remains compatibility language, not execution authority.

## Unresolved UNKNOWNs

- Decision-management leaf commands such as `decisions review`/`decisions list` are referenced by older docs and startup hints, but no runtime callbacks were found in `src/dopemux` during this pass.
- Several command families delegate to external services whose runtime health cannot be proven from help output alone: Docker/MCP, launchd routing, tmux, task-orchestrator, Repo Truth Extractor, ConPort, dope-memory, and GitHub PR merge operations.
- Commands classified as read-only from source inspection may still read local config, environment variables, or service health endpoints at execution time.
